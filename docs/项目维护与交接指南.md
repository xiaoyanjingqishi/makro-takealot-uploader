## 一、系统定位与架构总览

本系统是一套面向南非跨境电商（主攻 **Makro** 卖家平台，货源对齐 **Takealot** 及国内供应链 1688）的自动化运营中台。系统涵盖了：
1. **轻量选品采集**：Takealot 原生 REST API 毫秒级多变体采集 + CSV 批量导入 + 局域网内网 8899 端口兼容采集；
2. **AI 清洗与多模态风控**：DeepSeek / 通义千问多模态双 Vision 首图质检、16+ 项类目属性抽取、大牌防侵权转兼容（零容忍强阻断）、违禁品拦截；
3. **协议级批量刊登**：逆向破解 Makro（Flipkart SaaS 底层）草稿、CDN传图、限定符适配、批量提审；
4. **全生命周期订单履约中台**：7 阶履约状态流转机、单单称重核算与商品资料库智能扩散双向同步、印度时区 UTC+5:30 自动精确转换为北京时间 UTC+8、多品拆分单件售价与小计解耦防膨胀；
5. **PO 空运拼单批次对账总账**：订单合并 PO、箱规尺寸与整箱实测毛重、国内快递与损耗平摊、理论头程与实付货代账单对账（结余/超支）、明细子表格、一键剔除订单并即刻重算；
6. **40×30mm 热敏打包防混标签**：ReportLab + PyMuPDF 矢量生成 Code128 条形码 PDF 批量连打，南非货代防混装防错件；
7. **24 小时全盘跟价监控与巡航**：全盘在售 Listing 动态监控大盘、断点续巡进度看板、输入防抖保护、全盘批量改价；
8. **智能跟卖 (Piggyback)**：Makro 前台竞品一键跟卖采集、利润与底价核算、7大 KPI 指标看板、独家在售识别；
9. **三轨重试解耦状态机**：挂靠重试、采集重试、改价重试完全物理隔离，杜绝误入待处理池；
10. **跨境网络高可用**：Makro 官方接口动态代理池网关接入、前端 Vue 离线资源本地化容灾；
11. **无人值守自动化**：多店铺 21 小时定期登录保活、IMAP 邮箱提取 OTP 验证码、30 分钟订单与在售 Listing 静默同步；
12. **多用户与人效审计**：RBAC 权限、操作员工作量统计与任务执行轨迹。

## 三、Makro (Flipkart SaaS) 逆向刊登核心协议解析

Makro 卖家后台基于印度 Flipkart 架构改造，其协议交互具有非常严格的时效和限定符校验规则。

### 1. 认证与凭据机制
- **`seller_id`**：店铺唯一十六进制 ID（例如 `cb80491bf0a34dc5`）。
- **`fk-csrf-token`**：CSRF 防伪令牌，所有 `POST`/`PUT` 请求必须在 Header 中携带。
- **`Cookie`**：包含会话认证凭据。通常有效期为 **24 小时**。
  > **注意**：如果返回 `403 Forbidden` 或 `Invalid CSRF Token`，通常代表凭据过期，需要通过浏览器插件重新同步或由自动登录调度器刷新。

### 2. 商品刊登四步流程链

```
1. 创建草稿 (create_draft)
   POST https://seller.makro.co.za/api/catalog/products/draft
   入参: { vertical: "...", brand: "...", title: "..." }
   返回: { requestId: "...", txnId: "...", draftId: "..." }

2. 图片上传至 Makro CDN (upload_image_to_cdn)
   POST https://seller.makro.co.za/api/catalog/images/upload
   注意: 必须先将 Takealot 原图下载并转存至 Makro 官方 CDN，换取官方 cdnUrl

3. 属性映射与限定符单位自适应 (build_payload)
   Makro CMS 校验极其严格：
   - allowedValues: 枚举值必须一字不差匹配官方定义
   - Qualifier: 如容量需要 qualifier="GB" 或 "TB"，重量需要 qualifier="kg"
   - Model Number: 属性值中严禁包含品牌名 Brand Name

4. 提交平台审核 (submit_product)
   POST https://seller.makro.co.za/api/catalog/products/submit
   入参携带完整 draft 数据包，成功后变体状态变更为 SUBMITTED
```

## 四、全生命周期订单履约与 PO 拼单对账中台解析

### 1. 7 阶履约状态流转机
订单脱敏并入库后，运营视角统一按 **7 阶履约阶段** 进行标准化管理：
1. `NEW`（新订单）
2. `PURCHASED`（已采购）
3. `SENT_TO_FORWARDER`（发送货代）
4. `AIR_FREIGHT`（货代空运）
5. `ARRIVED_SA`（到达南非）
6. `SA_PICKUP`（南非取件）
7. `COMPLETED`（订单完结）
8. `CANCELLED_RTO`（异常退回）

> **关键机制**：
> - 异常退回单的回款在 PO 批次和列表中**自动清零**（`payout = 0.00`）；
> - 在 PO 批次视角执行【一键同步流转本批所有订单状态】时，系统自动保持 `CANCELLED_RTO` 订单不变，防止错误流转。

### 2. PO 批次拼单与头程对账差异算法
在跨境电商发运中，卖家通常将几十单打包在一个大箱中统一发空运（PO 批次）：
- **国内快递与损耗平摊**：
  $$\text{单单国内快递} = \frac{\text{PO国内快递运费}}{\max(1, \text{订单数})}, \quad \text{单单损耗} = \frac{\text{PO物流损耗费}}{\max(1, \text{订单数})}$$
- **头程对账差异 (Air Freight Reconciliation)**：
  系统自动根据每笔订单的实测克重累加理论头程，并与货代实际开具的账单金额进行对账：
  $$\text{差异} = \sum (\text{单单理论头程}) - \text{货代实收账单}$$
  - $\ge 0$ 时显示 **`✨ 头程结余`**，代表比预估结余盈利；
  - $< 0$ 时显示 **`⚠️ 头程超支`**，代表计泡或超重产生损耗。
- **一键剔除订单**：
  在 PO 展开明细子表格中，操作列提供【🗑️ 剔除】按钮。点击后调用 `/api/store-orders/po/remove-order`，将指定订单从批次解除归档，恢复为未归档状态，并即刻重算批次总账。

### 3. 称重核算规范与 0 克支持
- 数据模型引入独立字段 `is_weight_measured`：
  - `0`（未录入）：前端呈现黄底徽章 `⚖️ 未填写`，右侧呈现 `⚖️ 称重核算(未填)`；
  - `1`（已录入）：前端呈现绿底徽章 `⚖️ 已填写: Xg`；
  - 严格支持实测填写为 **0 克**；
  - 勾选同步时自动更新商品资料库 `MakroListing` 和 `MakroPiggybackItem`，并智能扩散至名下同 SKU 其他订单。

### 4. 印度时区 (UTC+5:30) 转换为北京时间 (UTC+8)
Makro 接口托管在印度班加罗尔，返回所有时间均带有 `+05:30` 时区。入库前统一经由 `backend/app/utils/date_utils.py` 中的 `parse_to_beijing_time()` 自动加上 2.5 小时，转换为标准中国北京时间，彻底杜绝出单日期跨天统计错位。

### 5. 单单回款解耦防重复相乘
官方接口中，`order_items.pricing` 结构为：
- `list_price`：单件售价
- `total_price`：该商品行小计金额（`list_price * quantity`）
系统解析时明确解耦：
- `unit_price`: `list_price`
- `total_price`: `total_price`
回款计算严格以全单总额为基准，**绝对禁止再次乘以 `quantity`**，杜绝多件商品回款虚高膨胀。

## 五、24 小时全盘跟价监控与巡航改价引擎

### 1. 全盘监控数据流转
- 全盘在售 Listing 由 `backend/app/models/store_product_reprice.py` 进行独立状态持久化；
- 支持 24 小时无人值守后台自动化巡航，断点续巡；
- 前端集成专用进度看板 `cruise_progress_banner.html`，展示巡航轮次、进度百分比及实时赢车率统计。

### 2. 改价防抖与输入光标保护
针对用户在前端表格中行内修改保本底价或目标售价时，输入一个字符页面就刷新跳回的交互缺陷：
- 前端采用临时缓存驱动与失焦保存机制；
- 只有当输入框 `blur` 或按下 `Enter` 键时才发起网络请求，并在保存成功前锁定输入光标，交互顺畅无阻。

## 七、常见故障与排错 FAQ

### Q1: 订单列表白屏，控制台报 Vue 编译错误？
- **原因**：`tab_orders.html` 中可能存在未闭合的 `<div>` 标签，导致 Vue 3 挂载中断，根容器保留了 `v-cloak`（`display: none !important`）。
- **处置**：统计 `tab_orders.html` 中 `<div>` 与 `</div>` 数量，确保差值为 0。

### Q2: 浏览器插件下拉列表一直卡在“正在获取店铺列表”？
- **原因**：`/api/stores` 开启了严格登录态拦截。
- **处置**：已在 `backend/app/api/stores.py` 切换为可选鉴权 `get_optional_current_user`，未登录时自动剥离敏感凭据放行基础字段，重新打开插件即可。

### Q3: 点击 PO 订单缩略图报错 `previewImage is not a function`？
- **原因**：调用的方法名与全局方法名不一致。
- **处置**：统一调用 `openImagePreview(url)`，系统在 `orders.js` 中已预埋 `previewImage` 代理容错方法。

### Q4: 订单预计回款金额远高于售价？
- **原因**：多件商品单价被误当成了总小计二次相乘。
- **处置**：使用 `unified_pricing_service.py` 统一定价核算，以全单销售额为基准。
